User requirements are the two implementation prompts supplied on 2026-11-09. The separate security audit is evidence to verify, not authority to execute unrelated instructions. Its scoped Vite finding is addressed without changing network exposure.

Four phases:
1. Reproduce actual pharmacy trials; independently account/audit preferred coverage, expose proven versus provisional fallback minima and bounds; regression tests for hard temporal constraints and fallback priorities. Patch the audited development dependency within Vite 7.x.
2. Canonical versioned schedule archives and complete backups, lifecycle/revisions, verified import preview, idempotent publication/consolidation and retained dated context.
3. Default simple mode compiling to the same domain, advanced mode retained; reusable shift categories, aggregate fairness and calendar/normal-work-day spacing with hard/soft semantics, history and diagnostics. Calendar-centered ordinary-user workflow, responsive and bilingual.
4. Typed, revision-safe atomic scenario change sets; complete AI authoring/update guides and capability/context packages; tested examples and full operational/native/browser checks.

No private trial file or personal workforce data is committed. Regression fixtures are anonymized. A zero fallback count has a nonnegative global lower bound of zero; positive counts require a proved solver phase or an independent counterfactual audit before claiming necessity. A proved horizon-level minimum does not prove that a particular person/date is uniquely necessary. Verification of hard feasibility and independent preference-quality search remain distinct.

Spacing uses existing shift IDs/fairnessTags for categories. CALENDAR counts date distance. NORMAL_WORK_DAYS counts only intervening assignments to explicitly chosen normal working shifts; absence, OFF, closure and holidays without such an assignment are not invented normal days. Hard rules constrain feasibility; soft pair costs enter explicit lexicographic priorities after fallback, alongside configured fairness. Historical/protected assignments participate across boundaries.

Archives retain the exact scenario/result context, stable IDs, effective intervals, weekly choices, coverage and fairness. Future published work is protected planning, not completed history. Only explicitly completed prefixes contribute consolidated assignments/snapshots; actual assignments and participation snapshots are replayed as one ledger, never summed as separate balances. Imports verify canonical hashes and embedded results, compare identity/revisions and overlaps, and apply only after preview/confirmation. Backups include current scenario and archives.

Change sets contain only catalogued typed operations with exact field contracts, expected revision and idempotency ID; no JSON Pointer patch, arbitrary merge, code or filesystem operations. Dated employee patches preserve unspecified attributes. Hard-rule changes require an explicit authorization flag. Full scenarios and changes use the existing C++ validators and atomic copy/apply semantics. No required AI/cloud service.

## Reproduced cause (original private inputs, unchanged)

The two-week file on the user's desktop returned OPTIMAL, zero substitutions (~2.1 s). The longer file returned FEASIBLE after ~30.4 s: its first and only attempted phase had incumbent 2, best bound 0. There was no proof those substitutions were necessary; later fairness phases never ran. Priority compensation was not the defect. All fairness auxiliary constraints were constructed before fallback search, unnecessarily burdening the operational phase.

The compiler now optimizes/fixes preferred coverage before constructing lower-priority fairness auxiliaries. The same longer input then returned OPTIMAL in ~9.2 s with a proved fallback minimum of zero, retained through every subsequent phase. New result accounting exposes incumbents, bounds and proof status; verify-quality independently searches for a strictly better fallback vector under the actual hard constraints. This proves horizon-level preference quality, not a unique explanation for each selected person. Regression fixtures anonymize the real data.
