# Guided configuration and work-pattern assignment · 0.3

Four phases: (1) centralized accessible operation notifications and dependency-ordered navigation; (2) schema-3 dated work-pattern assignment rules in the existing core; (3) visual rules/overrides, core previews and safe catalogue edits; (4) regression/browser/native distribution checks.

Schema 1/2 individual assignments remain unchanged. Schema 3 adds optional workPatternAssignmentRules: stable ID/label, enabled, existing selector, workPatternId, nonnegative priority (higher wins), validFrom and optional exclusive validTo. Resolution uses active employment, dated/default attributes and existing dynamic groups. Precedence: effective employee-version pattern override, explicit base pattern, highest-priority enabled/effective automatic rules, no pattern (existing unrestricted behavior). Equal top priority with different patterns is a diagnostic; ties pointing to the same pattern are compatible. A schema-3 version may set workPatternId:null to return to automatic resolution for that interval, suppressing the base assignment. Omitting that field continues to inherit the base. No employee fields are populated as a side effect of automatic resolution.

Domain/variants/verifier resolve through the same core function. Pattern preview validates workforce dependencies separately from unfinished operational configuration and uses the same resolver, without altering solve validation. Preview returns employee origins, rule IDs, matching counts and conflicts; it does not claim an invalid scenario is verified. Migration is explicit and preserves IDs/history/individual assignments. Retain dated rules and arrangements for historical boundary interpretation.

Operation outcomes use a bounded, deduplicated notification center fixed to the viewport bottom. Errors remain until dismissed; non-success solver statuses never become success merely because HTTP succeeded. Full diagnostics remain accessible. Field incompleteness stays contextual. Numbered guidance is advisory and distinguishes not started, incomplete, locally coherent and detected error; only core validation establishes whole-scenario validity.
