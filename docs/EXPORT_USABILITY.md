# Calendar export and quiet daily operation · 0.5

The 0.4+ export prompt is followed by its overriding quiet-interface addendum. Four implementation phases:

1. One native read-only calendar projection, shared filters/presets and export dialog. Canonical schedule-archive JSON remains complete and unchanged.
2. Offline downloadable PDF with real font metrics/pagination and matching preview; RFC 5545 UTC events from native resolved time zones, split intervals, personal ZIPs and stable event identities. Inspect actual generated files.
3. Calendar-first simple operation with a single evidence-based operational state, exception messages, optional counts and progressive technical diagnostics. Short validated change forms, reviewed revisions and explicit actual-work confirmation.
4. Contextual optional AI requests, human-readable change previews, bilingual/accessibility/regression checks and release documentation.

The optimization model is unchanged. A filtered view is never a historical source. Actual assignment intervals and dated native selectors are authoritative. Hidden shifts, rest, absence, inactivity, exclusions, closure and unplanned cells have distinct representations. Shared exports use generic unavailability; detailed reasons require an explicit choice and existing data. UTC conversion uses the native UTC/Europe-Rome transition resolver, including folds; unsupported or unresolved times block ICS rather than using an invented offset.

Publication remains separate from solution status. A completed prefix does not publish remaining dates. Manual ICS imports are file exchange, not synchronization or a guarantee of removing old events. Preferences live separately in browser storage.

## Daily workflow and acceptance

The default surface shows calendar/period, one operational state, relevant exceptions and Generate / Modify planning / Export calendar / Publish calendar. Duty distribution is a factual optional table; detailed fairness, lexicographic phases, bounds, seed, hashes, native verification and search controls remain in Advanced or explicit diagnostics. Routine success notifications are suppressed in Simple mode. JSON key ordering and an unchanged publication receipt do not make an otherwise identical calendar stale. Hidden advanced surfaces are unmounted; background previews use one native request slot.

The export dialog shares the same native view with the visible calendar. Presets cover full, closing/special categories (choose the configured category), personal, role/department, absence/rest and custom selections. All dates are inclusive and source bounded. Personal files use safe unique names; no hidden employees are serialized into their event data. Local filter/export preferences are separate from the scenario and never remember authorization to disclose absence reasons. PDF page layout is computed once for preview/download; a changed option invalidates the prepared download until the new preview is ready.

Quick forms provide availability, closure, future standard hours, hiring, enumerated contract attributes, work patterns and regeneration. The native transaction supplies revision/entity preconditions, protected work checks and human review. A conflicting official period can be previewed as a future proposal; publication explicitly supersedes the old archive. Confirmed actual history stays intact. Actual-work recording rejects future dates in the panel and requires an explicit attestation at review. Low-level CLI completion remains an explicit dated operation suitable for deterministic/offline imports; it does not infer today or proof that work occurred.

Optional contextual AI requests contain the user's wording, selected dates/IDs, current schema/version/revision, native context and relevant authoring guides. Default packages omit names, availability records, actual assignments and full history. Selected-person contexts omit unrelated employee records. Full personal scenario inclusion is opt-in. Import uses the existing strict typed contract, displays human summaries, requires authorization for hard-rule changes and never publishes or confirms work automatically.

Acceptance mapping: native `calendar_exports` covers source-bounded/custom filtering, dated roles/groups, actual variants/DST/folds, distinct hidden/rest/absence/excluded states, privacy, unchanged archives, CSV escaping, protected future hours and original-encoding regeneration. Independent file tests cover compact single-person and complete multi-person PDF, A4/A3 and all layouts, 104-page long-name stress output, real page counts/text, split/overnight/DST events, personal ZIPs and stable UIDs/lifecycle revisions. Existing archive/change-set tests retain canonical recovery, fairness continuation, duplicate replay, overlap rejection and hard-rule authorization. Browser paths cover ordinary PDF export/filter/phone flow, Italian errors/private calendars, reviewed HR revision→differences→publication, optional expert evidence and explicit completed-work confirmation. The quiet addendum replaces the original request's KPI dashboard criterion.

Reproduce file checks after a native build: `python -m pip install -r tests/requirements-exports.txt`, then `cd playground && npm run test:exports`. Set `EXPORT_PYTHON` and `ROSTERCORE_CLI` for alternate executable paths. Generated QA files live under ignored `tmp/pdfs`; render with `pdftoppm` for layout inspection. PDF is capped at 1,000 pages and missing font glyphs or unresolved ICS times fail explicitly.

## PDF day exclusions and named print profiles

In **Export calendar → PDF**, **Days to omit from PDF** removes date columns/rows, rather than just hiding state labels. Choose holidays, closures, rest (including weekly rest), excluded dates/weeks, uncalculated/unplanned periods, absence/unavailability, no active employees or other non-working dates. **Exclude all days with no work** selects every category. Categories combine by OR. Classification is computed natively from the complete original calendar before people, shift and display filters; a date with any actual WORKING assignment is always retained, including a working holiday or work hidden by a filter. Unknown legacy evidence is retained conservatively. Dates outside the saved calendar were already unavailable for printing; no additional uncalculated period is invented.

The same filtered date list drives weekly/monthly/person PDFs and their pagination preview. Empty weeks disappear, and omitting every date produces an actionable error instead of a blank printout. The printed period remains the selected inclusive range. These are PDF presentation choices: CSV, ICS, canonical archives, scheduling and historical accounting remain unchanged.

**Print profiles** saves named copies of the current people/shift/date filters, day exclusions, PDF layout, paper/orientation, headings and notes. Select a saved profile to load it. Edit its settings and use **Save as new print profile** with a distinct name to retain both variants, or explicitly **Update selected print profile**. Loading/editing never overwrites a saved profile automatically. Duplicate names are rejected; profiles can also be deleted without changing the current print settings. Profiles remain in this browser under `rostercore.print-profiles.v1`, separate from authoritative scenario/backups.

Saved dates are clipped to an overlapping source period; otherwise the current date selection is retained. Missing people, role/group and shift IDs are removed; an empty normal-shift definition turns off hide-normal. The current UI language is retained. Absence-reason authorization is always reset and never persisted. The previous unnamed export preferences remain readable through **Load previous export preferences**, then can be saved under a name. Invalid saved profile data is preserved and reported rather than silently overwritten.
